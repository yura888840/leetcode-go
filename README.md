# LeetCode на Go: решение через тесты

Требуется установленный Go 1.22 или новее. Внешних зависимостей нет.
`main.go` не нужен: точка входа при работе — `go test`.

## Быстрый старт

Распакуйте архив и откройте терминал в папке `leetcode-go`:

```bash
go test ./... -v -count=1 -timeout=30s
```

В проекте есть:

- `problems/p0001_two_sum/` — готовое решение и пять проверок; образец организации задачи.
- `problems/p0003_longest_substring/` — упражнение с десятью готовыми тестами, без решения.
- `template/` — заготовка для копирования.

Каждая папка — отдельный Go-пакет. Имена функций в разных задачах могут совпадать.
`solution.go` содержит решение, `solution_test.go` — тестовые случаи.
Все файлы используют `package solution`, поэтому тестам доступны функции со строчной буквы, как на LeetCode.

## Начать упражнение

Откройте `problems/p0003_longest_substring/solution_test.go` и удалите `t.Skip(...)`.
Нужно найти длину самой длинной **непрерывной подстроки** без повторяющихся символов.
Например, для `abcabcbb` ответ 3 (`abc`), для `bbbbb` — 1 (`b`).
Тестовые строки в этой заготовке используют ASCII.

```bash
go test ./problems/p0003_longest_substring -v -count=1 -timeout=30s
```

Сначала тесты упадут с `not implemented`. Реализуйте функцию в `solution.go`
и запускайте тесты снова. После успешного решения добавьте свои пограничные случаи.
Шаблон и упражнение намеренно пропущены через `t.Skip`, пока вы их не активируете;
зелёный запуск всех тестов сам по себе не означает, что эти задачи решены.

## Новая задача

На macOS/Linux, из корня проекта:

```bash
cp -R template problems/p0015_three_sum
```

1. Замените `solve` на сигнатуру функции из задачи.
2. Измените поля таблицы, входные данные и ожидаемые результаты в тесте.
3. Обновите вызов функции и проверку результата, удалите `t.Skip(...)`.
4. Запустите тесты новой папки, затем реализуйте решение.

```bash
go test ./problems/p0015_three_sum -v -count=1 -timeout=30s
```

Для массивов вместо `got != want` можно использовать `slices.Equal(got, want)`
из стандартного пакета `slices`; для вложенных структур — `reflect.DeepEqual`.
Учитывайте, что `reflect.DeepEqual` различает nil-срез и пустой срез.
Если порядок результата не важен, нормализуйте его или проверяйте свойства ответа:
в Two Sum тест проверяет индексы и сумму, принимая оба порядка индексов.
Для задач, меняющих входной массив на месте, проверяйте также изменённый массив.

## Полезные команды

```bash
# Все задачи, без кеша результатов
go test ./... -count=1 -timeout=30s

# Одна задача, подробный вывод
go test ./problems/p0001_two_sum -v -count=1

# Один конкретный тестовый случай
go test ./problems/p0001_two_sum -run '^TestTwoSum$/^duplicates$' -v -count=1

# Форматирование и статический анализ
go fmt ./...
go vet ./...
```

Есть и необязательные короткие команды Makefile:

```bash
make test
make one P=p0001_two_sum
make fmt
make vet
```

В VS Code или GoLand можно запускать отдельный тест прямо из редактора.
Для отправки на LeetCode копируйте функцию и необходимые вспомогательные определения
из `solution.go`, без строки `package solution` и без тестов; импорты добавляйте при необходимости.
Локальные тесты проверяют только заданные вами случаи и не заменяют скрытые тесты платформы.
